# 表征学习与嵌入驱动的多模态因子

LLM 作 feature engineering

核心思路：用 LLM/embedding 把大量非结构化内容（10-K、MD&A、分析师笔记、新闻语料、宏观评论）编码为连续向量或主题表征，把这些表征作为因子输入到现有的量化模型（因子回归、机器学习回归、深度时序模型）。

具体用例：

- 把公司年报的 MD&A/风险段落 embedding，构造“风险语义强度”因子预测未来波动或下行风险。
- 对宏观评论或央行声明建时序语义向量，作为宏观情绪因子加入资产配置或风险模型。
- 将财报数字与文本嵌入做交叉特征（文本+数值）用于信用/违约预测或长期动量因子。

技术实现要点：

- 嵌入策略：选择 domain-adapted LLM（或先做 domain-specific fine-tune），对不同文档片段做时序化嵌入（rolling windows），从而捕捉语义随时间的演化。
- 特征工程：对高维嵌入做 PCA/因子分解或用自注意力网络提取可解释主题；还可以做聚类、主题强度时间序列，再把聚类标签/主题强度当作可交易因子。
- 与价格时序融合：把嵌入特征作为外生变量输入 GRU/LSTM、Temporal Fusion Transformer、或作为 XGBoost 的额外列。
- 模型验证：严格使用时间序列交叉验证（滚动窗口），避免未来信息泄露。

评价指标 & 风险：

- 指标：因子 IC、信息比率提升、对基准模型的解释力增益、回测收益提升的统计显著性。
- 风险：特征冗余/多重共线性、过度拟合（高维嵌入很容易 fit 噪声）、计算成本高。
- 缓解：正则化、稀疏化/剪枝、使用稳定性选择（stability selection）、控制特征更新频率。

可做的快速试验：

把最近 10 年的 10-K MD&A 段落嵌入，做主题聚类并计算每家公司主题暴露的时间序列，检验主题暴露的滞后 IC（例如当期 vs 下一季收益/波动）。

设计思路、数据与预处理、embedding 策略（模型选择、分片/聚合）、向量存储与索引、如何从 embedding 构造可交易因子（具体方法与数学定义）、把因子并入模型与回测的实践细节、监控/治理、MVP 实验与资源估算、常见陷阱与缓解。

把各种非结构化文本（10-K、MD&A、财报电话会议转录、新闻、分析师报告、央行声明、行业报告等）编码为向量或主题时间序列，把这些语义表征转换为可用于预测收益、波动、下行风险或资产配置的量化因子。目标是：在不直接依赖“黑箱”句子级信号的情况下，建立稳健、可解释、可监控的文本因子体系，与结构化因子并行使用以提高信息比率（IR）和预测能力。

目标总结（一句话）：把企业文件、新闻、电话会、宏观文本等编码成向量/主题时间序列，把这些语义表征作为因子或外生变量接入机器学习/深度学习模型，从而提升长/中期 alpha 或风险预测能力。

## 设计原则

### 1. 总体思路与价值主张

- 语义丰富：文本能捕捉数字难以表达的“语气、关注点、风险主题、管理层变化”等。
- 多模态融合：文本嵌入能与数值因子（财务、价格）结合，构建更完整的表征。
- 长期/结构性信号：适用于信用、波动预测、基本面主题驱动的中长期因子。

### 2. 数据准备与预处理

输入范畴：

- 年报（10-K/20-F）和 MD&A 段落
- 季报和 8-K 重要段落
- 财报电话会议转录（ASR后）
- 行业新闻、分析师报告、宏观声明（央行、财政部）
- 社媒摘要（可选）

预处理步骤：

- 文档切分（sentence/paragraph/chunk），对长文档做固定窗口分片（例如 512–1024 token），带 overlap（例如 20%）以保持上下文连贯性。
- 统一清洗（去 HTML 标签、转义字符、数字标准化、日期标准化）。
- 语言归一（若跨语言，视团队能力决定翻译或使用多语言 embedding 模型）。
- 维持元数据：doc_id, asset_id, publish_time, section。

### 3. Embedding 设计决策

模型选择考量：

- 开箱嵌入（如 Sentence Transformers、OpenAI embeddings） vs domain-finetune。
- 对金融语料建议：先用通用 embedding，再做 domain-adapter 或用 contrastive fine-tune（把相似段落拉近，不相似推远）。

粒度选择：

- 片段级（chunk-level）：能捕捉文中局部主题，便于做短期/事件驱动因子。
- 文档级：对长期主题（公司战略）更稳定。
- 通常做两层：chunk-level embedding + 文档聚合（平均/加权/attention）。

池化与聚合：

- 平均 pooling、CLS token、attention pooling（如利用池化网络）或用一个轻量 Transformer 做聚合以得到 document embedding。

向量维度：常见 768 / 1024 / 1536 / 3072 等；维度越高表示能力越强但成本高。

- 若 embedding 维度 = 1536，每个 float32 占 4 字节：1536 * 4 = 6144 bytes = 6,144 bytes (≈6 KB)。
- 1,000,000 条文本的存储：6,144 * 1,000,000 = 6,144,000,000 bytes ≈ 6.144 GB (十进制)，约 5.72 GiB (二进制)。

### 4. 向量存储与检索（Vector DB）

选项：FAISS、Milvus、Pinecone、Weaviate 等。

索引类型：

- IVF + PQ（压缩，节省存储）适合离线大规模检索；
- HNSW（近似最近邻，低延迟，高精度）适合实时查询。

工程要点：

- 保存元数据（doc_id、asset_id、publish_time）与向量分离：向量索引做近邻检索，结果通过 doc_id 回查源文本与时间。
- 版本化：每次模型或参数更换都需要重新 embed 并存储版本号，便于回溯。
- 冷热分层：近期文档放在低延迟索引，历史文档放离线索引以节约成本。

### 5. 如何从 embedding 构造因子

1. 主题/聚类因子：
   - 对 embedding 做 K-means 或 hierarchical clustering → 得到 topic_id。
   - 每篇文档对于若干主题的暴露度（soft-assignment）可以成为 time-series 因子（topic intensity）。
2. 语义距离/novelty：
   - novelty_t = distance(embedding_t, historical_centroid)：新颖度高通常提示信息不对称或重大新闻。
3. 情绪/语气因子：
   - 建立一个“情绪轴”（通过标注或用情感模型训练），把 embedding 在该轴上的投影作为 sentiment_score。
4. 波动性预测因子：
   - semantic_volatility = stddev(embedding_series)：管理层语气或报告主题的突然变化可预测未来波动。
5. 实体/主题耦合因子：
   - 把公司 embedding 与行业/宏观主题 embedding 做相似度匹配，得到 “暴露到宏观主题 X 的强度” 作为因子。
   
### 6. 把 embedding 因子并入模型（融合策略）

- 直接做为特征：把 embedding 的低维表示（PCA 后的前 k 个分量）加入到 XGBoost / LightGBM 或线性因子模型。
- 时序模型：把 embedding 时间序列作为 exogenous input 输入到 LSTM/GRU/TFT/Transformer 进行预测（例如用于收益/波动/信用违约）。
- 图模型：构建公司-主题图（edges = similarity），用 GNN 来传播主题冲击。
- 交叉特征：embedding 与数值特征（PE、momentum）做交互项，捕捉“文本在不同基础面下的不同信号强度”。

### 7. 降维与可解释性

降维工具：PCA、SVD、Autoencoder（稀疏）、NMF（更易解释）、UMAP/T-SNE（仅用于可视化）。

解释方法：

- 对 topic cluster 抽取 top-k 的代表句/关键字，让人类给标签；
- 使用 LIME/SHAP（对后端模型）来估计 embedding components 对预测的贡献；
- 定期生成“主题词云”与代表段落，以便 PM/研究员审查。

### 8. 训练与验证（时间序列严格性）

- 时间切分：滚动窗口（rolling window）/ expanding window 的时序 CV；禁止随机 CV。
- 指标：每期计算 IC（因子与未来收益的相关）、R² 提升、信息比率、回测的收益 & 稳定性。
- 显著性检验：用 bootstrap 检验 IC 是否稳定；用样本外回测确定非显著的因子。
- 稳健性检查：剔除极端文档、不同聚类数/不同嵌入模型对结果是否稳健。

### 9. 在线 vs 离线：部署与更新策略

离线批处理（适合周/月级因子）

- 定期 (daily / weekly / monthly) 重新 embed 新文档并更新特征表。
实时在线（适合短期/热点主题）
- 新文档 arrival → 实时 embed → 更新实时特征/alert → trigger short-term策略。
- 缓存 embedding；仅在文档新增或模型版本变更时才 re-embed。
- 保持 embedding 版本并在回测中能指定使用哪个版本。

### 10. 监控 & 漂移检测

信号层面：

- embedding 分布统计（mean distance, variance）与历史 baseline 比较，检测漂移。
- topic 强度时间序列异常检测（突然飙升可能是事件或噪声）。

模型层面：

- 监控 IC 路径、预测误差的变化、回测 P&L 回退。
运维告警
- 自动阈值触发（如 novel_score 超 99%ile）并发起人工审查。

### 11. 常见风险与缓解

- 语义漂移：语言使用随时间改变，需定期重训 embedding 模型或用 continual learning。
- 过拟合高维向量：使用降维、正则、稳定性筛选避免噪声因子。
- 多语种问题：如果包含多语种文本，要么翻译，要么使用多语种模型并做语言特征分离。
- 向量索引失效：索引参数不当会导致检索 recall 下降，需监控检索质量指标。

## 实现细节

### 一、整体架构（简要流程）

1. 数据采集（原文 + metadata + 时间戳 + ASR confidence）
2. 文档预处理与切分（chunking）
3. Embedding（模型选择、批量推理、版本化）
4. 向量索引（Vector DB / FAISS / Milvus） + 元数据存储（Postgres/ClickHouse）
5. 因子构造（主题暴露、novelty、semantic volatility、sentiment 等）
6. 因子存储（Feature Store）→ 与价格/交易数据对齐
7. 建模与回测（IC、A/B、时序 CV）
8. 部署（离线/实时）、监控、治理、再训练

### 二、数据与预处理（必须要牢靠）

1. 输入数据类型与元数据（必存）
   - doc_id（唯一）
   - asset_id（若无则 null）
   - source（10-K, transcript, Reuters…）
   - publish_time（原始发布时间，UTC） 关键：所有因子/回测都以此为准
   - ingest_time（我们收到时间）
   - language
   - asr_confidence（若为语音转写）
   - raw_text（原文）
   - clean_text（清洗后，用于 embedding）   
2. 清洗与切分（chunking）
   - 为什么要切分：大文件（10-K）很长，embedding 模型有上下文限制；切分便于并行化与主题级表征。
   - token window: 512–1024 tokens（取决于模型上下文窗口；常用 512）
   - overlap: 64–128 tokens（保持上下文衔接）
   - chunk 最少长度阈值：50 tokens（太短的 chunk 可合并）
   - 策略：
   - 基于段落优先（尽量按自然段落切）；若段落太长再按 token 切。
   - 保留 chunk-level metadata：doc_id, chunk_idx, start_char, end_char, section_tag（如 MD&A、RiskFactors）
   
### 三、Embedding 策略（核心技术决策）

1. 模型选择与 trade-off
   - 选择维度：质量 vs 成本 vs 延迟 vs 多语种。
   - 可选项（工程上常见）：
     - 开源 sentence-transformers（快速本地部署，低成本）
     - 商业高质量 embeddings（例如 OpenAI、Anthropic embeddings）：质量高但成本与合规要求高
     - domain-adapted models：在金融语料上做 adapter 或 contrastive fine-tune 提升表现
   - 建议起步：用开源的 sentence-transformers（如 all-mpnet-base-v2）做 MVP；对关键任务再做 domain-adapter 微调（contrastive learning：把相似段落拉近）。
2. Embedding 维度与存储估算（务必逐位算清）
   - 常用维度：768、1024、1536。
   - 单向量存储（float32）大小计算逐位示例（以 1536 维为例）：
     - 每个 float32 = 4 bytes。
     - 1536 × 4 = 6,144 bytes（逐位计算：15364 = 1536(22) = 30722 = 6144）。
     - 1,000,000 条向量占用：6,144 × 1,000,000 = 6,144,000,000 bytes。
     - 6,144,000,000 bytes ≈ 6.144 GB（十进制）。
   - 结论：选择维度须平衡效果与存储/索引成本。
3. Batch 推理与吞吐
   - 批量化推理（batch embedding）能显著提高 GPU/CPU 利用率。
   - 为实时路径准备轻量模型或 CPU-优化实现；把高质量大模型作为离线批处理重算版本。
4. 版本化
   - 每次模型、tokenizer、或微调参数变更都要写入 embedding_version 字段并保留原始向量，便于回溯。
   
### 四、向量索引与元数据存储

1. 选型
   - 实时检索（低延迟）：HNSW（Milvus、Pinecone、Weaviate）
   - 离线大规模（低成本）：FAISS IVF+PQ 索引
   - 建议架构：近期数据驻留 HNSW（快速检索），历史数据存 FAISS 低成本索引；二者按时间分层。
2. 索引与元数据设计
   - 向量索引只存 vector_id 与 embedding（和索引结构）；元数据（doc_id、asset_id、publish_time、section）存到关系/列式数据库（Postgres/ClickHouse）或 ElasticSearch。检索后用 vector_id 回查元数据表获取原文与时间信息。
   
## Embedding 因子

### 1. Topic Exposure（主题暴露）

定义与构造：

- 对全部 chunk embedding 做聚类（KMeans，K=50~100），得到主题中心 ${c_k}$。
- 对每个 chunk 得到 soft assignment 概率 $p_{c,k}$；公司/报告期层面按权重（长度/时效）聚合：

$$
\text{TE}_{i,t,k}=\frac{\sum_{c\in C_{i,t}} w_c\, p_{c,k}}{\sum_{c\in C_{i,t}} w_c},\quad \sum_k \text{TE}_{i,t,k}=1
$$

- 可再做降维（PCA/SVD）或保留 top-m 主题以稀疏化。

从因子到“方向性”信号：主题本身不带方向，需要用历史数据学习每个主题的报酬系数（按回测持有期 Δ 分别估计）：

$$
r_{i,t\to t+\Delta}=\alpha + \sum_{k=1}^{K} \beta_{k,\Delta,t}\,\text{TE}_{i,t,k} + \gamma^\top X_{i,t} + \varepsilon_{i,t}
$$

- $X_{i,t}$：控制变量（行业/市值/估值/动量等）。
- 训练方式：滚动窗口 Ridge/Lasso（防多重共线），得到 $\hat\beta_{k,\Delta,t}$。
- 于是得到期望收益预测（主题 alpha）：

$$
\hat\mu^{(topic)}_{i,t,\Delta}=\sum_k \hat\beta_{k,\Delta,t}\,\text{TE}_{i,t,k}
$$

交易信号：

- 信号强度：跨截面 z-score

$$
S^{(topic)}_{i,t}=\text{zscore}_{i\in\mathcal{U}_t}\big(\hat\mu^{(topic)}_{i,t,\Delta}\big)
$$

- 方向：$S>0$ 做多、$S<0$ 做空（行业/国家中性化）。
- 持有期：10-K/MD&A 建议 1–3 个月；电话会主题变化可 2–4 周。
- 退出：信号衰减到 |z|<0.3，或到期 Δ 后强平；触发再披露（新文档）则重算。
- 增强：加入“主题动量” $\Delta \text{TE}$（主题权重的滚动变化），在回归中单列，常能提升 IC。

### 2. Novelty / Surprise（新颖度）

定义与构造：

- 针对公司 $i$ 的新文档/片段向量 $v_c$ 与历史窗口（如 180 天）均值 $\mu_{i,\text{hist}}$ 的余弦距离：
  
$$
\text{novelty}_{c}=1-\frac{\langle v_c,\mu_{i,\text{hist}}\rangle}{\|v_c\|\,\|\mu_{i,\text{hist}}\|}
$$

- 公司层面聚合为当日/当周新颖度 $N_{i,t}$（加权平均后 z-score）。

注意：新颖度是“信息量”强弱，不含方向。

给出方向的方法，三种可共存

1. 与情绪联动

$$
S^{(nov)}_{i,t}=\text{zscore}\big(N_{i,t}\times \text{Sentiment}_{i,t}\big)
$$

   - 直觉：越“新”且“情绪越正/负”，后续同向漂移概率越高（类似 PEAD 的文本版）。
   - 持有期：新闻 1–5 天；财报文本 5–20 天。
2. “未反应”漂移（Underreaction）

若发布后短期价格反应 $|\text{ret}_{i,[t,t+1d]}|$ 很小（如 < 0.5%），但 $N_{i,t}$ 很大且情绪为正（或负）：

$$
S^{(nov)}_{i,t}=\text{sign}(\text{Sentiment}_{i,t})\cdot \mathbb{1}\{N_{i,t}>\tau_N,\, |\text{ret}_{i,[t,t+1d]}|<\tau_R\}
$$

   - 做多/做空，持有 3–10 天，博“延迟消化”。
3. 风险叠加（非方向 alpha，而是仓位调节）
   - $N_{i,t}$ 极端 ⇒ 未来波动高；将其作为 杠杆/止损 调节因子（见第 3 节联动）。
   
### 3. Semantic Volatility（语义波动）

定义与构造：

- 在滚动窗口内，文本向量的波动性（L2/余弦方差）：

$$
\text{SV}_{i,t}=\sqrt{\frac{1}{W}\sum_{c\in \mathcal{W}_t}\|v_c-\bar v_t\|^2}
$$

或 rolling pairwise cosine variance；再做对数化与 z-score 稳定。

用法：主要是“风险信号”，也可派生方向

1. 仓位调节：将其作为未来波动的预测量：

$$
\hat\sigma_{i,t+\Delta}=\text{EWMA}(\text{SV}_{i,t},\,\text{RV}_{i,t})
$$

位置权重：

$$
w_{i,t}\propto \frac{\hat\mu_{i,t}}{\hat\sigma_{i,t}^2}
$$

文本波动上升时自动降杠杆、缩小单票风险。

2. 波动交易/对冲
   - 若可做期权：SV↑ 预测未来实现波动↑，偏向买跨式/多波动。
   - 仅多空股票：构造“SV 因子 beta”并做 多低 SV / 空高 SV 的低风险套利（与低波动风格相近，但以语义驱动）。
3. 方向派生
   - 回归检验 $\Delta \text{SV}$ 与未来收益关系（某些行业信息不确定性上升会带来负超额回报），若显著再纳入 $\hat\mu$。
   
### 4. Sentiment / Tone（情绪）

定义与构造：

- 训练/选用金融域情绪模型，chunk 级评分 $\in[-1,1]$，源别加权聚合到公司/日：

$$
\text{Sent}_{i,t}=\frac{\sum_{c\in C_{i,t}}w_c\,s_c}{\sum w_c},\quad
w_c\propto \text{recency}\times \text{source\_reliability}
$$

- 做横截面标准化、winsorize（1%–99%）。

交易信号

- 跨截面多空：

$$
S^{(sent)}_{i,t}=\text{zscore}\big(\text{Sent}_{i,t}\big)
$$

行业/国家中性，新闻持有 1–5 天；电话会/10-K 持有 2–8 周（并设置日衰减）。

- 情绪冲击 + 反应不足：同第 2 节做联合门限（高情绪 × 小初始反应）。
- 情绪拐点：EWMA 平滑后做向上/下穿越（如从负转正并超过 +1σ），入场持有 5–20 天。
- 稳健聚合：用 trimmed mean/Huber 防极端值干扰；新闻去重（near-dup）。

### 5. Cross-Entity Spillover（跨实体溢出）

两类构造

1. 宏观/主题暴露
   - 预先定义宏观主题向量 ${m_k}$（如“通胀压力”“鹰派货币政策”），或从央行声明/宏评上游提取主题中心。
   - 公司暴露：$\text{Expo}_{i,k,t}=\cos(\text{Emb}_{i,t}, m_{k})$。
   - 宏观当期冲击：$M_{k,t}$（由当日宏观文本情绪/强度得到）。

期望收益：

$$
\hat\mu^{(macro)}_{i,t}=\sum_k \theta_{k,t}\,\text{Expo}_{i,k,t}\,M_{k,t}
$$

$\theta_{k,t}$ 由历史回归学习（或设为 1 先做 MVP）。

1.  同业/供应链溢出（事件传播）
    - 用文本相似度/知识图谱建邻接网络 $G$，相似度 $w_{ij}$。
    - 领导者公司 $A$ 在 $t_0$ 发布高新颖度、强情绪的事件，则对邻居 $j$ 生成信号：

$$
S^{(spill)}_{j,t}=\sum_{A\in \mathcal{L}_t} w_{jA}\cdot \text{Sent}_A(t_0)\cdot \text{decay}(t-t_0)\cdot \mathbb{1}\{\text{no\_own\_news}_j\}
$$

- 持有期：1–3 天（新闻扩散），或 1–2 周（供应链/行业慢传播）。

交易信号
- 宏观 Overlay：当“鹰派指数”上升（$M_{\text{hawkish}}>0$）时，降低对高利率敏感暴露（$\text{Expo}_{i,\text{duration}}$ 高）的多头权重，或做多低暴露/做空高暴露。
- 同业补涨/补跌：龙头先动、相似公司滞后 ⇒ 对高相似度、尚未发声的公司建同向仓位；成交/市值过滤，持有 2–5 天。

### 统一“出清”与仓位公式（把所有信号汇总）

1. 对齐与标准化
   - 所有输入以 publish_time(UTC) + 最小可实现延迟 $\delta$（如 30m/1d）入库。
   - 每日对可交易池 $\mathcal{U}_t$ 做行业中性 z-score、winsorize。
2. 合成期望收益

$$
\hat\mu_{i,t}=
w_T\,S^{(topic)}_{i,t}
+w_N\,S^{(nov)}_{i,t}
+w_S\,S^{(sent)}_{i,t}
+w_C\,S^{(spill)}_{i,t}
+\underbrace{w_O\,S^{(others)}_{i,t}}_{\text{可选}}
$$

   - 权重学习：滚动 Ridge 回归到未来收益、或按各因子 IR 分配 $w\propto \text{IR}^2$（稳健且自适应）。
3. 风险与约束
   - 未来波动预测：$\hat\sigma_{i,t}=\text{EWMA}(\text{SV},\text{RV})$；
   - 头寸（Kelly 缩放版）：

$$
\tilde w_{i,t}=\kappa\cdot \frac{\hat\mu_{i,t}}{\hat\sigma_{i,t}^2},\qquad
w_{i,t}=\text{Proj}_{\mathcal{C}}\big(\tilde w_{i,t}\big)
$$

其中 $\mathcal{C}$：行业/国家/因子中性、单票上限、净敞口、换手上限、流动性过滤等。

3. 执行与退出

- 进场阈值：$|\hat\mu_{i,t}|>q_{70}$（或 |z|>0.8）；
- 持有期：按来源：
  - 新闻/研报：1–5 天（日衰减 $\lambda\in[0.7,0.9]$）；
  - 电话会/10-K：2–8 周（周衰减）；
- 退出：信号回落（|z|<0.3）、持有超期、止损/止盈（ATR/波动倍数）。

## 关键实现细节与“坑点”提醒
- 防泄漏：主题聚类/PCA/回归的拟合只用“当时可见”历史，评估用滚动 CV。
- 稀疏化与稳健：主题保留 top-m；聚合用 Huber/trimmed mean；近重复新闻去重。
- 多重检验：对大量主题的 $\beta_k$ 做 FDR（BH 程序），防偶然显著。
- 中性化：先对 Size/Value/Mom/行业做正交化，看“纯文本 alpha”。
- 成本/换手：文本信号（尤其新闻）易高换手；加入交易成本模型与冷却期。
- 监控：滚动 IC/IR、覆盖率、漂移（embedding 范数/主成分）、故障告警（抓取/ASR/延迟）。

## 小结

- Topic：先学每个主题对未来收益的历史“方向系数” $\beta_k$，再用当期主题暴露线性合成成 方向性 alpha。
- Novelty：是“信息量”放大器，最好与情绪或初始价格反应结合决定方向；同时用于风险加权。
- Semantic Volatility：主要是风险控制与仓位调节，必要时可做“多低/空高”的风格套利。
- Sentiment：直接、有效的方向 alpha（短到中期），注意源别权重、平滑与去重。
- Spillover：把宏观与龙头事件通过“相似度网络”传播成同业/上下游信号与宏观 overlay。

### 1. Topic Momentum（主题动量）

定义：

对每个主题 $k$ 和公司 $i$：

$$
\text{TM}_{i,t,k} = \text{TE}_{i,t,k} - \text{EWMA}\big(\text{TE}_{i,t-\tau:t-1,k};\lambda\big)
$$

对公司层面汇总（可选加权）：

$$
\text{TM}_{i,t}=\sum_{k} w_k \,\text{TM}_{i,t,k}
$$

其中 $w_k$ 可以是历史回归得到的主题收益系数 $\hat\beta_k$，或简单取 top-K 主题绝对变化加权平均。

直觉/假设：

主题暴露从历史水平快速上升（或下降）代表叙事正在加速，常预示未来价格有趋势性移动（延续性或反转性在回测中验证）。

可解释性：

可展示贡献最大的主题及对应代表片段（top-N chunks），便于 PM 理解“哪个话题在推动动量”。

实现要点：

- EWMA 半衰期选择：10–60 天试验。
- 先对 TE 做 industry-neutral / size-neutral 后再算动量，减少风格偏差。
- 计算每个主题的历史 $\hat\beta_k$ 以权重化，需滚动拟合避免泄漏。

信号构造：

- 标准化：跨截面 z-score。
- 方向：TM>0 → 倾向做多（若 $\beta_k>0$），反之做空。
- 强度：|z| 大者入场。
- 持有期：短中期（5–30 天），根据主题半衰期调整。

坑/监控：

- 高噪主题可能产生虚假动量 → 只使用有稳定 $\beta_k$ 的主题。
- 监控：主题贡献度分布、TM 的 autocorr 与IC。

### 2. Narrative Concentration Index（叙事集中度，NCI）

定义：

利用主题暴露分布计算（K 主题）熵（normalized）：

$$
H_{i,t} = -\sum_{k=1}^{K} \text{TE}_{i,t,k}\,\log(\text{TE}_{i,t,k})
$$

归一化：

$$
\text{NCI}_{i,t} = 1 - \frac{H_{i,t}}{\log K}\quad\in[0,1]
$$

NCI 越接近 1 表示叙事非常集中（少数主题占主导）；接近 0 表示话题分散。

直觉/假设：

- 高集中度意味着市场/媒体把某一主题强烈聚焦，往往伴随更明确方向或更大波动（正或负）。
- 低集中度意味着“杂乱无章”，预测力较弱。

可解释性：

直接用主题贡献可视化（饼图 / top-3 topics），PM 一看便知哪个主题主导。

实现要点：

- 用 K 选取使大多数日子的 NCI 分布有分辨力（K~50）。
- 对短文本（新闻）与长文本（10-K）分别计算再合并，避免被长文主导。

信号：

1. 方向放大器：当 NCI 高且情绪方向明确（均为正或负），放大仓位。
2. 风险开关：NCI 高但情绪混合 → 减仓（因为集中但方向不一致意味着不确定性/分裂舆论）。

持有期：随主题 persistence（见 Topic Decay）而定，通常 3–30 天。

坑/监控：

- NCI 单用不带方向；务必与情绪/novelty 配合。
- 监控 NCI 的时间序列、行业基线与极端阈值。

### 3. Topic-Specific Sentiment Delta（主题情绪差分）

定义：

针对某个高影响力主题 $k$：

$$
\Delta \text{Sent}_{i,t,k} = \text{Sent}_{i,t,k^*} - \text{EWMA}(\text{Sent}_{i,t-\tau:t-1,k^*})
$$

其中 $\text{Sent}_{i,t,k}$ 是在主题 $k$ 下的聚合情绪（只用被分类为该 topic 的 chunks）。

直觉/假设：

主题内部情绪快速变好/变差，比总体情绪更具方向性（例如“guidance”主题情绪变差往往预示盈利下调）。

可解释性：

可以逐主题展示代表文本与情绪变化的时间图。

实现要点：

- 主题情绪用金融情绪模型分类，source-weight（管理层>公司公告>媒体）权重化。
- 主题选择：事先标注一组 high-impact topics（如 guidance、liquidity、regulation）。

信号：

- 直接方向：ΔSent > 0 → 做多（若历史上对该主题的 $\beta>0$）
- 持有期：一般 5–30 天（主题相关性强时更久）。
- 与 price reaction 联合：若 ΔSent 大而初始 price reaction 小，则更可入场（underreaction 策略）。

坑/监控：

- 主题识别错误会污染该因子；需人工审核 top examples。
- 监控：主题 chunk 数量（覆盖率）与 sentiment 标注置信度。

### 4. Sentiment Surprise（情绪惊讶）

定义：

情绪相对公司历史（或行业期望）的偏差：

$$
\text{SS}_{i,t} = \text{Sent}_{i,t} - \text{ExpSent}_{i,t}
$$

其中 $\text{ExpSent}_{i,t}$ 可以由历史 EWMA、行业基线或基于 LLM 预测的“预期情绪”得到。

直觉/假设：

正的情绪惊讶如果未被股价充分消化（price reaction 小），则可能带来后续回报。

可解释性：

把 surprise 与 price reaction 的联合分布展示；可找出“延迟反应”窗口。

实现要点：

- ExpSent 模型：可简单用 EWMA 或用回归预测情绪的季节性/行业效应。
- 需要监控新闻覆盖与 sentiment confidence。

信号：

- 条件交易：SS large & |initial_ret| < threshold → 同向建仓。
- 持有期：极短（1–7 天）为主。
- 拓展：用作 alpha 源，对流动性较差小盘有更强效果（但成本高）。

坑：

- 高换手 / 高频事件导致交易成本高；必须评估成本敏感性。

### 5. Semantic Leadership（语义领先度 / Topic Leadingness）

定义（估计）：

对每个主题 $k$ 计算行业级主题时间序列 $M_{k,t}$（行业均值 TE）并与全市场或其它行业做交叉相关（cross-correlation）：

- 计算跨时间的相关函数 $\rho_{k}(\ell)$（lag = $\ell$）。
- 如果 $\arg\max_{\ell}\rho_k(\ell) = \ell^* < 0$，说明该主题在平均上领先（负 lag 表示主题变化先于行业变化）。

定义主题领先强度：

$$
L_k = \max_{\ell\in[-L,L]} \rho_k(\ell)\cdot \mathbb{1}(\ell^<0)\cdot \frac{|\ell^|}{L}
$$

公司得分：

$$
\text{Lead}_{i,t} = \sum_k \text{TE}_{i,t,k}\, L_k
$$

直觉/假设：

公司在“领先”主题上的暴露越高，越有可能成为该主题后续行情的“驱动器”或获益者（尤其在创新/行业变革类话题）。

可解释性：

可以列出哪些主题是“领先主题”，以及公司在这些主题上的例句。

实现要点：

- 计算 $L_k$ 要用长窗口（数年）并做行业分组，需稳定性测试。
- 使用 bootstrap 检验 $\rho$ 显著性，避免噪声领先度。

信号：

- 高 Lead → 做多（持有期根据主题半衰期：1个月至数季度）。
- 可与 Topic Momentum 合并：领先×上升 表示强信号。

坑/监控
- 主题“领先”可能是数据异步/抓取延迟造成，需要校验。
- 监控：主题领先性的历史稳定性、bootstrap p-value。

### 6. Cross-Entity Herding（同业从众度 / Herd Score）

定义：

公司当期 embedding 与同行 embedding（同一行业或供应链圈）平均相似度：

$$
\text{Herd}_{i,t} = \frac{1}{|\mathcal{P}_{i}|}\sum_{j\in\mathcal{P}_{i}} \cos\big(v_{i,t}, v_{j,t}\big)
$$

也可以按市值/影响力加权。

直觉/假设：

- Herd 高：信息/话题高度“从众”，在 negative news 时可能造成系统性回撤（放大跌幅）。
- Herd 低：公司更“独立”，其公告更可能产生 idiosyncratic alpha。

可解释性：

给出与公司最相似的同行名单和代表文本，PM 可直观看到“谁在说相同的话”。

实现要点：

- 选择 peers：行业 + supply-chain graph 或 top-N 最相似历史公司。
- 控制重复新闻（避免同样新闻抓取导致高相似度假象）。

信号：

- 风险叠加器：Herd↑ 时降低仓位（尤其在市场情绪负时）。
- 或构造风格对冲：多低 Herd / 空高 Herd（与低波动策略类似但基于语义）。

坑：

- 抓取延迟和 wide syndication（新闻转载）会错误放大 Herd；需去重并按 unique source 计数。

### 7. Narrative Volatility Clustering Index（语义波动聚集）

定义：

检测最近窗口（例如 90 天）内语义波动（SV）极值的聚集度。令事件 $E_{i,t}=1$ 当 $\text{SV}_{i,t} > \mu_{\text{SV},i}+c\cdot\sigma_{\text{SV},i}$。定义聚集指数为：

$$
\text{NVCI}_{i,t} = \frac{\sum_{s=t-W+1}^{t} E_{i,s}}{\sqrt{\text{inter-event variance}}}
$$

或简单用 K-interval count/Poisson overdispersion 测度。

直觉/假设：

波动事件的集群出现通常预示 regime change、新闻流集中或潜在下行风险。

可解释性：

展示异常事件时间点与对应文本，便于追溯。

实现要点：

- 选择窗口 W 与阈值 c（例如 c=2）。
- 可以区分“上行波动事件”和“下行波动事件”。

信号：

- 用作风险开关：NVCI↑ → 降杠杆、加大止损保护。
- 如果 NVCI↑ 且情绪正向（少见情形），可能是信息密集但利多 → 可选择捕获。

坑：
- 高频新闻源会制造很多“小”事件，需按影响力加权。

### 8. Management Consistency Score（管理层一致性）

定义：

比较管理层（CEO/CFO）在电话会/采访中的表达与公司正式文件（10-K/press release）的相似度与情绪差：

$$
\text{MCS}_{i,t} = \alpha\cdot \cos(\overline{v}_{\text{mgmt},i,t}, \overline{v}_{\text{filing},i,t}) - \beta\cdot |\text{Sent}_{\text{mgmt}}-\text{Sent}_{\text{filing}}|
$$

或分两项：相似度与情绪差的分数。

直觉/假设：

管理层言辞与公司文件高度不一致时可能提示信息传递问题（如 “spin” 或隐含风险），反之一致性高表明信息透明。

可解释性：

展示具体引文差异和情绪对照，PM 可判断是否为沟通策略或真实差异。

实现要点：

- 需要 speaker attribution（ASR+NER）把话语归于 CEO/CFO。
- 控制时间窗（只比较同一财报期内的管理讲话与 filings）。

信号：

- 高不一致（低 MCS）：偏向做空或做风险对冲（持有期取决于违信事件显现速度，通常 1–3 月）。
- 也可作为事件筛查器，触发人工复核。

坑：

- ASR 错误与 speaker mismatch 会污染分数；对 ASR confidence 做阈值过滤。

### 9. Readability / Legal-Jargon Index（文本复杂度）

定义：

基于传统可读性指标（Flesch-Kincaid、avg sentence length、legal-term ratio）或用 embedding 投影到“复杂度轴”：

$$
\text{RLI}_{i,t} = \gamma_1 \cdot \text{avg\_sent\_len} + \gamma_2\cdot \text{percent\_legal\_tokens} - \gamma_3\cdot \text{lexical\_simplicity}
$$

直觉/假设：

文本复杂度高、法律术语多，可能掩盖负面信息或风险披露（与未来下行风险相关）。

可解释性：

列示高复杂度句子与关键法律表述供审查。

实现要点：

- 用金融法律词典标注 legal tokens 或用 small LLM 检测“obfuscation”句子。
- 归一化为 z-score 跨公司比较。

信号：

- RLI↑ → 提高风险对冲权重或做防御性仓位（降低杠杆/减仓）。
- 亦可触发人工查证（合规层面）。

坑：

- 行业内基线不同（法律行业文本自然复杂），需行业标准化。

### 10. Event Probability Classifier（监督式事件概率因子）

定义：

训练监督模型（XGBoost/LightGBM / small transformer）用 embedding features、topic exposures、sentiment 等预测标签事件 Y（例如：earnings surprise > x，credit downgrade，restatement，guidance cut）。输出概率：

$$
p_{i,t}^{(event)} = \Pr(Y_{i,t+\Delta}=1\mid \text{features}_{i,t})
$$

直觉/假设：

直接把文本映射到可交易事件概率，事件驱动策略更直接且可解释（“概率越高，越应对冲或建立仓位”）。

可解释性：

用 SHAP/代表文段展示模型为什么给出高概率（哪些短语/主题贡献最大）。

实现要点：

- 需要可靠标注数据（历史事件标签）。
- 处理样本不平衡（SMOTE / class weights）。
- 输出校准（isotonic/Platt scaling）。

信号：

- p > threshold → 触发对冲或空仓（如预测 downgrade）。
- 若预测 positive event（beat guidance），做多并设止损。

坑：

- 模型过拟合历史标签；需严格 purged walk-forward 验证与冷启动测试。

### 11. Topic Decay Half-Life（主题半衰期）

定义：

对某公司某主题时间序列 $\text{TE}_{i,t,k}$，估计自相关函数 $\rho(\ell)$，拟合指数衰减并计算半衰期 $T_{1/2}$：

$$
\rho(\ell) \approx e^{-\ell/\tau_k}\quad \Rightarrow\quad T_{1/2} = \tau_k\ln 2
$$

直觉/假设：

- 主题半衰期短：主题是短期事件；持仓期应短。
- 半衰期长：主题构成长期趋势，可持仓更久且加权增大。

可解释性：

给出主题 persistence 排行，便于策略设计“持有期匹配”。

实现要点：

- 需要平滑系列并移除季节效应；对每个主题按行业分层估计更稳。
- bootstrap 半衰期置信区间。

信号/使用：

- 用于仓位时间尺度分配：仓位规模 ∝ sqrt(T_{1/2}) 或直接把持有期设为约 T_{1/2}。
- 与 Topic Momentum 结合：高动量+长半衰期 → 强持仓信号。

坑：

- 混合频率文本（news vs 10-K）会影响估计，需要分源估计再合并。

### 12. Cross-Modal Conviction（跨模态置信度）

定义：

把文本信号（$\hat\mu^{text}$ 或 $p_event$）与结构化数值 surprise（earnings surprise, revenue surprise, balance sheet signal）结合：

$$
\text{CMC}_{i,t} = \sigma\big( a\cdot \hat\mu^{text}_{i,t} + b\cdot \text{num\_surprise}_{i,t} + c\cdot \text{vol\_signal}_{i,t} \big)
$$

或更 interpretable：

$$
\text{CMC} = \frac{\hat\mu^{text}}{\text{std}(\hat\mu^{text})} \times \frac{\text{num\_surprise}}{\text{std}(\text{num\_surprise})}
$$

把结果映射到 [0,1]（sigmoid 或 min-max），表示“文本与数值一致性的置信度”。

直觉/假设：

当文本与数值同时指向同一方向时，预测更可靠，适合增加杠杆或长期持有。

可解释性：

报告“文本贡献 %、数字贡献 %”与代表性内容。

实现要点：

- 标准化各模态分数后再乘/线性组合。
- 注意数字信号的发布时间（earnings release 的 timestamp）和文本的 publish_time 对齐。

信号：

- CMC 高：放大仓位，较长持有期；CMC 低：降低仓位或仅做短期试探性仓位。
- 可做分层：CMC>0.8（核心仓），0.5–0.8（战术仓），<0.5（不交易或小仓）。

坑：

- 不同模态发布时间不一致会误导组合信号，必须严格按 publish_time 对齐。

### 因子验证与组合

1. 数据准备
   - 为每个因子保证明确的 visible_ts，并记录 source、embedding_version、chunk_count。
   - 每个因子需要 coverage ≥ 某阈值（如 60% 在池内公司），否则别纳入跨截面比较。
2. 单因子回测
   - 横截面 IC（daily）与 rolling IC（30/90/180d），用 Newey–West t-stat 检验显著性。
   - 分层分析（行业 / 市值 /市盈分位）。
3. 多因子合成
   - 先用 Ridge 回归估计合成权重（rolling training，防泄漏），也可按 IR 分配权重 $w\propto \text{IR}^2$。
   - 重要：对每因子做 industry/size neutralization 与 winsorize。
4. 交易化
   - 构造权重：$\tilde w_i \propto \frac{\hat\mu_i}{\hat\sigma_i^2} \cdot g(\text{risk\_factor})$（risk_factor 包括 NVCI、Herd 固定项）。
   - 强制约束：单票限额、行业中性、流动性过滤、最大换手。
   - 成本模型（impact + spread）必须嵌入回测。
5. 稳健性/稳定性
   - 检验 rolling IR、跨时间段（牛熊）、不同 embedding_version 的稳定性（如果因子随 embedding 版本剧烈变化，则不稳）。
   - 做 stability selection（例如 LASSO bootstrap）筛出稳定贡献的主题/特征。
6. 解释与交付
   - 对每个回测期或当前信号，导出 top-5 文本片段贡献项 & 主题标签，便于 PM/合规审查。
   - 记录 run_id 与版本，所有回测可复现。
   
### 优先级

1. Topic Momentum（主题动量） — 直接且容易映射到方向性 alpha；解释性强（主题示例）。
2. Topic-Specific Sentiment Delta（主题情绪差分） — 结合主题可得到高命中率，尤其对 guidance/liquidity 类主题。
3. Narrative Concentration Index（叙事集中度） + 用作仓位放大/降权开关 — 用于风险控制，减少假信号换手成本。

随后依次开发：Semantic Leadership（需长时间序列统计），Event Probability Classifier（需标签数据），Management Consistency（需要 speaker attribution/ASR）。

- 每个新增因子上线前：rolling 180 天 IC mean > 0.01 且 t-stat > 2（或按你的门槛），覆盖率 > 40%。
- 上线后：30/90/180 天 IR、因子贡献占组合 PnL 的比率、换手率与成本占比。
- 漂移告警：embedding norm 或主成分变化超出历史 3σ；因子 IC 突然下降 >50%。

## 附录：实现细节

### 一、数据预处理与 Embedding 策略

数据与元数据（必存）：

- doc_id（唯一）、asset_id（若无则 null）、source（10-K, transcript, Reuters…）
- publish_time（原始发布时间，UTC）——关键：所有因子/回测都以此为准
- ingest_time（我们收到时间）、language、asr_confidence（若为语音转写）
- raw_text（原文）、clean_text（清洗后，用于 embedding）

清洗与切分（chunking）：

- 为什么要切分：大文件（10-K）很长，embedding 模型有上下文限制；切分便于并行化与主题级表征。
- token window: 512–1024 tokens（取决于模型上下文窗口；常用 512）
- overlap: 64–128 tokens（保持上下文衔接）
- chunk 最少长度阈值：50 tokens（太短的 chunk 可合并）
- 策略：基于段落优先（尽量按自然段落切）；若段落太长再按 token 切。保留 chunk-level metadata：doc_id, chunk_idx, start_char, end_char, section_tag（如 MD&A、RiskFactors）

示例伪代码（Python）：

```python
def chunk_document(text, tokenizer, window=512, overlap=128):
    tokens = tokenizer.encode(text)
    chunks = []
    i = 0
    while i < len(tokens):
        chunk_tokens = tokens[i:i+window]
        if len(chunk_tokens) < 50 and chunks:
            # append to last chunk
            chunks[-1]['tokens'] += chunk_tokens
        else:
            chunks.append({'tokens': chunk_tokens, 'start': i, 'end': i+len(chunk_tokens)})
        i += window - overlap
    # convert tokens back to text snippets if needed
    return chunks
```

Embedding 策略（核心技术决策）：

1. 模型选择与 trade-off
   - 选择维度：质量 vs 成本 vs 延迟 vs 多语种。
   - 可选项（工程上常见）：开源 sentence-transformers（快速本地部署，低成本）；商业高质量 embeddings（例如 OpenAI、Anthropic embeddings）：质量高但成本与合规要求高；domain-adapted models：在金融语料上做 adapter 或 contrastive fine-tune 提升表现。
   - 建议起步：用开源的 sentence-transformers（如 all-mpnet-base-v2）做 MVP；对关键任务再做 domain-adapter 微调（contrastive learning：把相似段落拉近）。
2. Embedding 维度与存储估算（务必逐位算清）
   - 常用维度：768、1024、1536。单向量存储（float32）：1536 × 4 = 6,144 bytes（≈6 KB）。
   - 1,000,000 条向量占用：6,144 × 1,000,000 = 6,144,000,000 bytes ≈ 6.144 GB（十进制），约 5.72 GiB（二进制）。
   - 结论：选择维度须平衡效果与存储/索引成本。
3. Batch 推理与吞吐
   - 批量化推理（batch embedding）能显著提高 GPU/CPU 利用率。
   - 为实时路径准备轻量模型或 CPU-优化实现；把高质量大模型作为离线批处理重算版本。
4. 版本化
   - 每次模型、tokenizer、或微调参数变更都要写入 embedding_version 字段并保留原始向量，便于回溯。
   
### 二、向量库选型与元数据存储

选型：

- 实时检索（低延迟）：HNSW（Milvus、Pinecone、Weaviate）
- 离线大规模（低成本）：FAISS IVF+PQ 索引
- 建议架构：近期数据驻留 HNSW（快速检索），历史数据存 FAISS 低成本索引；二者按时间分层（冷热分层）。

索引与元数据设计：

- 向量索引只存 vector_id 与 embedding（和索引结构）；元数据（doc_id、asset_id、publish_time、section）存到关系/列式数据库（Postgres/ClickHouse）或 ElasticSearch。检索后用 vector_id 回查元数据表获取原文与时间信息。

```postgresql
CREATE TABLE doc_chunks (
  vector_id TEXT PRIMARY KEY,
  doc_id TEXT,
  asset_id TEXT,
  publish_time TIMESTAMPTZ,
  chunk_idx INT,
  section TEXT,
  snippet TEXT,
  embedding_version TEXT
);
```

### 三、时序对齐

时间对齐原则（绝对关键）：

- 所有因子基于 publish_time（UTC）对齐，并在回测中模拟 ingest_delay（不同 source 不同延迟）。
- 因子在 publish_time 可见时刻被写入 Feature Store（或写入后在下一可交易 bar 使用）。

### 四、部署与漂移监控

在线 vs 离线：部署与更新策略

- 离线批处理（适合周/月级因子）：定期 (daily / weekly / monthly) 重新 embed 新文档并更新特征表。
- 实时在线（适合短期/热点主题）：新文档 arrival → 实时 embed → 更新实时特征/alert → trigger short-term 策略。
- 缓存 embedding；仅在文档新增或模型版本变更时才 re-embed。
- 保持 embedding 版本并在回测中能指定使用哪个版本。

Embedding 与索引监控：

- 平均 embedding 范围（mean L2 norm）、均值向量、向量分布（PCA 第一前两主成分）随时间变化。
- 检测语义漂移：新文档到最近历史 centroid 的平均 cosine 距离若显著上升，则触发重训练或人工审查。
- 信号层面：embedding 分布统计（mean distance, variance）与历史 baseline 比较检测漂移；topic 强度时间序列异常检测（突然飙升可能是事件或噪声）。

因子性能监控：

- 滚动 IC（30/90/180 天）、IC 的 p-value、因子分解的回撤贡献。
- 因子覆盖率（多少资产在过去 N 天有有效文本因子）与稀疏度。
- 数据质量告警：publish_time 延迟增加、ASR confidence 下降、文档抓取率下降。
- 运维告警：自动阈值触发（如 novel_score 超 99%ile）并发起人工审查。

审计与版本管理：

- 每次 embedding、kmeans、或降维操作都写入 model_registry：{model_name, model_hash, embedding_version, kmeans_version, date}。
- 所有 feature 作成操作记录 run_id —— 回测/生产能指定 run_id 重现数据。
