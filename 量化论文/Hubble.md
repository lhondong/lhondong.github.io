# Hubble

> **Hubble: An LLM-Driven Agentic Framework for Safe, Diverse, and Reproducible Alpha Factor Discovery**
> Runze Shi*, Shengyu Yan, Yuecheng Cai, Chenxi Lv（Celestial Quant Lab, Canada; The University of British Columbia）｜ arXiv 2604.09601，2026-03-09（v2: 2026-04-14）

## 摘要

自动化的 alpha 因子发现之所以困难，是因为公式化因子的搜索空间具有组合爆炸性，日度股票数据的信噪比很低，且不受约束的程序生成在操作层面是不安全的。本文提出 Hubble，一个智能体化（agentic）的因子挖掘框架，将大语言模型（LLM）与领域特定的算子语言、抽象语法树（AST）执行沙盒、双通道检索增强生成（RAG）模块以及家族感知选择机制相结合。Hubble 不将 LLM 视为不受约束的代码生成器，而是将生成限制在可解释的算子树范围内，通过确定性的横截面（cross-sectional）流水线评估每个候选因子，并将顶级公式以及结构化的家族级诊断信息反馈给后续轮次。当前系统还引入了正/负 RAG、公式相似度惩罚、标准化多指标评分、RankIC 与 Pearson IC 的双重报告，以及持久化的诊断产物。在美国约 500 只股票的样本上，主运行在三轮中评估了 104 个有效候选因子，且零运行时崩溃，发现的因子由 range（区间）、volatility（波动率）和 trend（趋势）家族主导，而非拥挤的纯成交量（volume-only）模板。随后，将得到的 top-5 因子固定，并在 2025-06-01 至 2026-03-13 的留外（hold-out）期间进行验证：两个 range 因子和两个 volatility 因子保持正值，且多个因子达到了 HAC 显著的 Pearson IC 和多空（long-short）证据，而样本内最弱的 trend 因子则明显衰减。这些结果表明，安全的 LLM 引导搜索可以从一个语法合规的生成器升级为一个可复现的 alpha 研究工作流，联合优化有效性、多样性、可解释性和家族级泛化能力。

## Introduction

作者提出 Hubble 的驱动力来自三个相互交织的困难：

1. **搜索空间巨大**：公式化 alpha 因子的假设空间呈组合爆炸增长，传统手工构造（如 101 formulaic alphas）耗时耗力且难以扩展；
2. **数据信噪比极低**：日度股票数据中有效信号微弱，自动化方法极易过拟合；
3. **操作安全性缺失**：直接将 LLM 用于公式/代码生成会导致不安全的代码执行、语义无效的表达式，以及重复发现拥挤模板等问题。

### 相关工作

- **遗传编程（GP）**：能高效探索大空间，但产生的表达式脆弱、难以解释、难以落地操作，且容易过拟合；
- **手工因子库（如 101 formulaic alphas）**：平衡了可解释性和组合性，但构建和扩展仍高度依赖专家劳动；
- **现有 LLM 驱动 alpha 挖掘（Alpha-GPT、AlphaAgent、FactorMiner）**：展示了语言引导搜索的潜力，但往往更强调生成质量，而忽视了执行安全、研究可复现性，以及对因子拥挤度和多样性的显式控制；
- naive LLM 公式挖掘的第四类故障模式：**收敛于低新颖性的狭窄信号集**——缺乏多样性控制的系统会扎堆于少数统计表现好但缺乏经济逻辑的信号。

核心假设与直觉：

1. **安全约束释放创造力**：将 LLM 限制在领域特定语言（DSL）和 AST 沙盒内，反而能避免崩溃和无效代码，使搜索更稳定、更可控；
2. **多样性控制改变赢家身份**：通过双通道 RAG（鼓励探索未被覆盖的机制 + 显式排斥拥挤模板）和家族感知评分，能从根本上改变最终入选因子的类型，使其从拥挤的成交量模板转向 range、volatility 等更分散的家族；
3. **机制级泛化优于公式级泛化**：框架更擅长发现稳定的因子家族/机制，而非保证每一个 top 排名的具体公式都能同等程度地泛化。

## 方法设计

Hubble 是一个**闭环智能体搜索系统**，由五个核心模块组成。输入为日度股票面板数据（OPEN、HIGH、LOW、CLOSE、VOLUME、VWAP）+ 算子注册表 + 可选的上下文反馈（前几轮历史）。

### 步骤 1：双通道 RAG 检索

每一轮从因子语料库中检索两类参考样本：**Positive RAG** 检索代表性公式或提炼模板，鼓励探索未被充分覆盖的机制（如 range、volatility）；**Negative RAG** 检索拥挤或过度探索的模板，作为 "avoid-like references"（应避免的类型）呈现给 LLM。两类引用与静态算子前缀、动态后缀（含生成指令、多样性要求、前一轮反馈）一起打包成 prompt。

### 步骤 2：DSL 约束生成

LLM 在受约束的算子注册表和动态 prompt 下生成候选公式。Prompt 明确要求主题多样性，覆盖 price trend、mean reversion、volatility、range、liquidity-volume、price-volume interaction 等家族，保证生成物是可解释的、语法合规的算子树，而非任意 Python 代码。

### 步骤 3：AST 安全沙盒验证

对生成的公式字符串进行三层验证：**结构安全**——只允许白名单内的 AST 节点类型（exec-free）；**复杂度控制**——超过预设深度或节点数量的表达式被拒绝；**语义有效性**——算子名称、元数（arity）、变量名必须全部属于已注册的 DSL。

### 步骤 4：确定性评估引擎

计算 **RankIC**（Spearman 秩相关系数）和 **IC**（Pearson 线性相关系数），以及年化信息比率 RankICIR 和 ICIR；额外计算覆盖率（coverage）、缺失率（drop ratio）、分桶收益（bucket returns）、多空收益（long-short return）、换手率（turnover，用 top-decile Jaccard distance 度量）、公式复杂度（AST 深度、节点数、算子数、窗口数）；显著性检验使用 Bartlett-kernel HAC 方差估计量（Newey-West 风格）计算 t 统计量。

### 步骤 5：标准化评分与家族感知选择

每个指标 $m_j$ 先通过 tanh 变换标准化：$\tilde{m}_j = \tanh\left(\frac{m_j - c_j}{s_j}\right)$，其中 $(c_j, s_j)$ 是预设的归一化常数。基础分数为：

$$
\text{score}_{\text{base}}(\alpha) = \sum_j w_j \tilde{m}_j(\alpha)
$$

最终分数为：

$$
\text{score}(\alpha) = \text{score}_{\text{base}}(\alpha) - \lambda_c P_{\text{crowded}}(\alpha) - \lambda_s P_{\text{similar}}(\alpha) - \lambda_f P_{\text{family}}(\alpha) + \lambda_n B_{\text{novelty}}(\alpha)
$$

- $P_{\text{crowded}}$：与 negative-RAG 拥挤模板的接近度惩罚；
- $P_{\text{similar}}$：与已选因子近似度的惩罚（去重）；
- $P_{\text{family}}$：同一家族内已有因子数量过多的惩罚（防止家族集中）；
- $B_{\text{novelty}}$：若该因子属于当前尚未被选中的家族，则给予奖励（鼓励家族扩展）。

选择时设置 **top-k family cap**（如每家族最多 2 个），强制多样性。

### 步骤 6：反馈与持久化存档

将本轮的 top 公式、错误摘要、家族诊断、RAG 标识符、prompt 元数据等打包为反馈，并持久化存储（append-only records、JSON 摘要、prompt/response 快照、诊断产物），形成闭环并保证研究过程可审计、可复现。

## 实现与结果

### 实验设置

- **数据集**：美国日度股票面板，标的来自 S&P 500，有效股票 501 只；
- **样本内（IS）**：2022-01-01 至 2025-05-31，共 840 个交易日；
- **样本外（OOS）**：2025-06-01 至 2026-03-13，共 195 个交易日，完全未在发现阶段使用；
- **评估指标**：RankIC、RankICIR（年化）、IC、ICIR（年化）、多空收益（LS Ret.）、换手率、覆盖率、HAC t 统计量；
- **关键设置**：3 轮、每轮候选数 20（含反馈批次后每轮评估数可达 30-40）、top-k = 5、top-k family cap 每家族最多 2 个；主模型 nvidia/nemotron-3-super-120b-a12b:free（通过 OpenRouter），稳健性模型 openrouter/hunter-alpha。

对比结论：

- Range-1 和 Range-2 在 OOS 中**显著增强**：Pearson IC HAC t 统计量分别达到 2.98 和 3.01（$p < 0.01$），多空收益 t 统计量分别为 2.17 和 2.31（$p < 0.05$）；

### 局限性

1. **未做中性化**：因子评估未对市场、行业或风格进行中性化，报告的 IC 和多空统计可能混入系统性风险暴露；OOS 期间区间和波动率因子的 IC 偏高，可能部分因为 2025–2026 年市场整体波动率较高；
2. **单一样本，无滚动样本外**：分析基于单一美国日度股票面板，OOS 仅是一个时间切分，而非滚动重训练研究；
3. **样本外窗口短且存在制度风险**：OOS 仅 195 个交易日，应视为初步留外证据而非无条件的 alpha 主张；
4. **RAG 语料库偏差**：RAG 语料库仍反映 curated 历史示例，可能保留早期实验的残余主题偏差；
5. **稳健性分析较轻量化**：更完整的公开版本应包含显式消融实验（如 RAG 开/关、标准化评分开/关）；
6. **无交易成本评估**：未进行完整的交易成本感知回测（Top 因子换手率 11–37%）；
7. **LLM 时间泄露**：LLM 的预训练语料必然包含 IS 窗口开始后发表的金融文献，模型可能内化了关于哪些因子家族有效的元知识；
8. **LLM 叙事偏差**：每个发现的因子都会附带一个看似合理的金融机制故事，解释的合理性会降低研究者的批判阈值，独立于统计证据之外。

### 后续方向

1. **中性化因子评估**：将市场 beta、行业、规模、价值、动量等风格因子中性化纳入评估流水线；
2. **滚动前向与多面板验证**：实施真正的 walk-forward 协议，并在多个市场和不同频率上验证；
3. **交易成本感知挖掘与组合优化**：将滑点、市场冲击、手续费和换手率约束直接嵌入因子评分函数；
4. **RAG 语料库的去偏与动态更新**：使负 RAG 能实时识别新兴拥挤区域；
5. **严格的消融实验**：系统性地开关各组件，量化每个模块的边际贡献；
6. **对抗性 LLM 时间防火墙**：使用在严格预发现语料上微调的开源模型，或引入"知识截止"约束；
7. **人机协同叙事审计**：将叙事从"自动验证"降级为"待检验的启发"；
8. **因子衰减实时监测与自适应替换**：形成"发现-验证-淘汰-再发现"的完整生命周期管理。

## 总结

用语法沙盒和正负检索双管齐下，让大模型安全地挖出多样且可解释的量化因子。

1. **给 LLM 划定语法禁区**：只允许用预定义算子组合公式，生成后过三层 AST 安检；
2. **正反双向喂参考**：既给优秀模板当榜样（positive RAG），也把拥挤旧因子当反面教材（negative RAG）；
3. **横截面体检每个候选**：算 RankIC、Pearson IC、换手率、多空收益，并用 HAC 做显著性检验；
4. **打分时不只看预测力**：用 tanh 标准化后，再扣掉"拥挤分""重复分""扎堆分"，奖励"开新家族分"；
5. **存档并反馈**：把 top 公式和家族诊断塞回下一轮 prompt，形成闭环。
